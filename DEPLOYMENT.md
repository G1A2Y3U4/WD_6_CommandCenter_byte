# Deployment

This project has a Vite frontend, an Express and Socket.IO backend, and a MySQL database. The deployment files target Vercel for the frontend, Render for the API, and TiDB Cloud Starter for a managed, MySQL-compatible database. TiDB's free quota is subject to its published limits; this app's MySQL driver uses TLS for that connection.

## 1. Prepare the database

Create a TiDB Cloud Starter cluster and a database named `kanban_db`, generate a database password, and add your deployment API's outbound IP access as required by the provider. Use its connection details (`host`, port `4000`, and user) as the Render environment values. `DB_NAME` is already set to `kanban_db`. Import [server/schema.sql](server/schema.sql) into that database using TiDB's SQL editor. This export contains schema only; local task and user records are not copied.

## 2. Deploy the API

Push the repository to GitHub, then create a Render Blueprint from the repository's `render.yaml`:

- The Blueprint defines the API with a free compute plan and prompts for database host, user, password, database name, and frontend origin.
- `JWT_SECRET` is generated by Render. `DB_PORT=4000` and `DB_SSL=true` are set for TiDB.
- After the frontend is deployed, set `CLIENT_URL` to its origin (for example `https://your-app.vercel.app`, without a trailing slash). Multiple origins can be comma-separated.

Render supplies `PORT` automatically. Once deployed, opening `https://YOUR-API.onrender.com/` should return a JSON status message.

## 3. Deploy the frontend

Import the same GitHub repository into Vercel and set:

- Root directory: `client`
- Framework preset: Vite
- Build command: `npm run build`
- Output directory: `dist`
- Environment variable `VITE_API_URL=https://YOUR-API.onrender.com/api`

The Socket.IO URL is derived from `VITE_API_URL`; set `VITE_SOCKET_URL` only if the socket endpoint is hosted at a different origin. Redeploy after changing environment variables. Then update the API's `CLIENT_URL` to the final Vercel domain and redeploy the API.

## 4. Check the live app

Open the frontend, register an account, log in, and create/update a task. If requests fail, check the browser console and the Render service logs. Confirm the deployed API can connect to the MySQL host and that the database tables and columns match the app's queries.

Render's free API service can spin down when idle. For local development, copy `server/.env.example` to `server/.env` and set your local MySQL credentials. In `client`, use a `.env.local` file containing `VITE_API_URL=http://localhost:5000/api` (or omit it to use the local default).
